# DeepSeek Harness

The repo's agent config is shared by Claude Code, Codex CLI, and DeepSeek Harness (DSH). The committed
sources are `agents/*.md`, `skills/*`, `AGENTS.md`, and each checkout's `/.mcp.json`; every harness
config directory (`.claude/`, `.codex/`, `.agents/`, `.dsh/`) is gitignored and generated by
`scripts/install-agent-config.sh`.

## Launching

```bash
scripts/install-agent-config.sh          # after cloning and in every new worktree
scripts/dsh                              # web profile, repo-scoped overlay
scripts/dsh web --port 8080              # the leading `web` is accepted and stripped
scripts/dsh --dump-config                # compose the overlay without starting the app
```

Use `scripts/dsh`, not plain `dsh web`. The overlay is passed with `--patch`, so it only applies to
the checkout you launched it from; the global `~/.dsh/profiles/web/cordis.patch.yml` is never edited.
A linked worktree gets its own overlay from `scripts/create-worktree.sh`.

The web profile is fixed because the role presets and `subagent_role` depend on the web bundle's
agent-preset registry. Use plain `dsh` for `headless`, `sdk`, and `acp`.

## What the overlay contains

`.dsh/profile.patch.yml` is generated by `scripts/gen-dsh-config.py`:

- **MCP tools.** Servers are merged in Claude Code's precedence: `~/.claude.json` `mcpServers`, then
  `~/.claude.json` `projects[<repo>].mcpServers`, then the checkout's `/.mcp.json`. `${VAR}`
  placeholders become `!!js` expressions resolved at DSH boot. Tools appear as
  `mcp__<serverName>__<tool>`.
- **Role presets.** Every `agents/*.md` is cloned from the shipped DSH `standard` preset with its
  `persona` replaced by the agent body and its frontmatter description attached. The same pass reads
  best-effort local agents in `.claude/agents` (real files, not the installer's symlinks) and user
  agents in `~/.claude/agents`.
- **`subagent_role`.** A host-level `@deepseek-ai/dsh-tool-subagent` instance exposes the generated
  presets as `agent_preset` choices, defaulting to the first role. Use it for specialist delegation;
  `subagent` and `subagent_fork` remain available for generic children.

`scripts/dsh --dump-config` is the quickest check that the overlay composes. Regenerate and restart
after changing `agents/*.md` or MCP config; the overlay is read at boot.

## Shared memory and skills

- `AGENTS.md` (and the `CLAUDE.md` symlink) is loaded by DSH's workspace-instruction plugin.
- `.agents/memory/MEMORY.md` is the project memory; read it before non-trivial work and record with the
  `project-memory` skill.
- `.agents/skills/*` is the DSH skill root. This includes the repo's skills, sibling skills linked by
  `EXTRA_SKILLS`, and any locally installed real directory (for example `playwright-cli`).
- `scripts/install-agent-config.sh --user` mirrors `~/.claude/CLAUDE.md` to `~/.agents/AGENTS.md` and
  links `~/.agents/skills` to `~/.claude/skills` when the latter exists, so user-level instructions and
  skills are shared too.

Skills and instructions follow the working directory, so a session launched in one repo can `cd` into a
consumer and pick up that consumer's `AGENTS.md` and skills. Host plugins do not move: MCP servers and
role presets are fixed at launch. Launch `../sts2-couch-coop/scripts/dsh` from the consumer when its
project MCP and roles are needed.

## spirectl

In `../sts2-couch-coop`, spirectl is used through the `spirectl` skill and its CLI, not through an MCP
server. The skill is linked into the consumer's `.agents/skills` by its installer, so no MCP entry is
needed or generated for it.

## Limitations

- The Claude/Codex `PreToolUse` guard is not wired into DSH; DSH's own approval policy and the rules in
  `AGENTS.md` are the guardrail.
- Claude's `tools:` and `model:` agent frontmatter is reported but not enforced; role presets inherit the
  standard tool set and the parent model.
- Role presets copy the shipped DSH `standard` composition, not local edits to `preset-standard` in the
  global profile patch.
- MCP definitions are mirrored; Claude OAuth/credential state is not.
- A role body containing `{{` is skipped because DSH would treat it as a persona template variable.
- One DSH server per repo for repo-scoped MCP and roles; a restart is required after regeneration.

## Troubleshooting

| Symptom | Cause | Fix |
| --- | --- | --- |
| `error: .../.dsh/profile.patch.yml is missing` | installer not run here | `scripts/install-agent-config.sh` |
| `DeepSeek Harness (dsh) is not on PATH` | non-standard install | `DSH_BIN=/path/to/dsh scripts/dsh` |
| No role presets, warning about `standard.patch.yml` | DSH package layout not found | set `DSH_PRESET_FILE` to `@deepseek-ai/dsh-web-app/presets/standard.patch.yml` |
| No MCP tools | server failed at startup, or no definition found | check the DSH log; `dsh --dump-config` shows the rows |
| Overlay changed but tools did not | host plugins load at boot | restart `scripts/dsh` |
