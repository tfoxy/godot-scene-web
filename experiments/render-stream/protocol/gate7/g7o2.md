### G7o2 — the Rust core's step-transaction cost on the g31 (opus; g31 runs unattended)

After G7x, G7xw and G7xwl, GSW's hd-patch is the one bench input over 0.5·T_p on the g31 (p95
13.0 ms against 8.51 ms). The web export on the Rust core misses on scene-full and hd-patch. G7o2
profiles the core on the phone, then cuts the work that sets the p95. No budget moves (D25, D27),
and nothing that D31 keeps on the frame path is skipped.

- **Files**:
  - `rs-core/src/prof.rs`: opt-in phase timers (off unless a clock is installed), and
    `prof::replay`, the GSW page's pipeline without GL.
  - `rs-core/src/apply/mod.rs`: the dependency re-lower and the applier micro-optimizations.
  - `rs-core/src/apply/payloads.rs`: `verify_decode`, and `PayloadStage`, the verified payloads
    that arrived ahead of the transaction that uses them.
  - `rs-core/src/bin/rs-core-check.rs`: `profile` and `walk-diff`.
  - `web/gsw-rs/src/lib.rs`: `stage_payload`, `provide_staged`, `payload_verify_json`, and the
    `corrupt-payload` and `verify-in-frame` shell sabotages.
  - `web/bench/bench-rs.ts`, `web/gsw-receiver/{main,live,fetcher,perf,common}.ts`: payloads
    verified when they arrive, with `payload_verify_us` outside `total_us`.
  - `rs-core-capi`, `receiver/ext/` and `receiver/{receiver,rs_rust_applier,rs_perf}.gd`: D31's
    deferred record digest in the web export's file mode on the Rust core.
  - `gate7-bench.ts`: the `gsw-rs-base` arm (`--rs-build-base`), `--web-bundle-base`,
    `--profile`, and cpufreq and thermal samples around every page.
  - `scripts/gate7x-checks.ts` and `scripts/run-g7x-sabotages.sh`: `payload-verified-before-use`.
- **Payload verification ahead of use.** D31 needs a resource payload's SHA-256 checked before
  the payload is used. It does not need the check inside the frame that applies it. A payload is
  verified against the hash it was fetched for, and decoded, when it arrives. In the receiver page
  that happens in the fetch's completion, between frames. In the bench, the fetcher holds every
  payload already, so its completion runs synchronously between accept and provide. The result is
  staged. The frame's `provide` then moves it from the stage into the store. A payload that fails
  its hash is refused when it arrives and nothing is staged, so no transaction can use it.
  A transaction whose payload is not staged waits, or fails, exactly as it does for a missing
  payload. Pins, retirement and the fetch log are unchanged. A refusal is raised where `provide`
  raised it before, so a failing leg's evidence is the same. The moved cost is its own timer,
  `payload_verify_us`, outside `total_us`, in the same way as D31's `evidence_hash_us`.
- **Record digest, web export.** In file mode on the Rust core, the web export defers the
  per-record digest, as D31 allows a browser receiver to. `RenderingServer.frame_post_draw` fills
  `record_sha256` for the transactions applied since the last frame. That time is
  `evidence_hash_us` in perf.json, outside `decode_us`. The native receiver and live mode keep the
  digest inline.
- **Checks**:
  - golden-2 to golden-7, natively and as wasm in Node, unchanged;
  - `walk-diff`: the incremental applier's paint digest equals an always-walk applier's for every
    transaction of the four bench inputs;
  - `payload-verified-before-use` (bench and receiver page): every payload a transaction used was
    verified against its hash before its first use. None was unverified, none was refused, and on
    a build that stages, none was verified inside the frame;
  - `record-digest-complete`: on GSW, and in the web export (receiver.gd fails
    `record-digest-incomplete` when an applied transaction has no digest at `_finish`);
  - every landed g7 group on GSW and on the web export on both cores, with file-leg shots
    byte-identical to `main`'s; the live groups on GSW and on web-rust; gates 0 to 6 natively on
    both cores (`receiver/` and `rs-core-capi` changed).
- **Sabotages** (`run-g7x-sabotages.sh`, pace-patch):
  - `corrupt-payload` flips one byte of every fetched payload. It must be refused before use
    (`payload-verified-before-use`, and the run errors with `resource-hash`);
  - `verify-in-frame` verifies inside the frame on a staging build (`payload-verified-before-use`);
  - `skip-payload-hash` stages a payload without its hash check (`payload-verified-before-use`);
  - the rs-core unit test `corrupted_payload_byte_is_refused_before_use`;
  - the existing `drop-draws`, `stale-item-row` and `digest-skip`.
- **Runs**: D32's protocol on the g31. That is the four inputs, one warmup and five repeats, the
  before and after arms interleaved, and cpufreq and thermal per page. GSW is
  `--interleave gsw-rs-base,gsw-rs` against `main`'s build. The web export on the Rust core is
  `--arm web --core rust --web-bundle-base` against `main`'s bundle. Judgment is p95 against
  0.5·T_p. A remaining miss is the typed finding `device-decode-over-budget`, with per-phase
  numbers.

#### As built

- **Profile first.** With phase timers on the g31, hd-patch's p95 is set by its step transactions
  (seq 1, 11, …, 101: 11 of 122). Each cost 12–26 ms. In seq 21, providing the payloads took
  5 ms: 2.2 ms of SHA-256 and 1.9 ms of decoding for a 256 KB texture. Applying took 5–7 ms
  (walk, text re-lower, classify and assemble), decoding 2–3 ms and drawing 2–5 ms. A mesh
  animates every frame, so 111 of 122 transactions walked (DEPENDENCY).
- **Dependency re-lower in place.** A mesh version or texture size change is now treated like a
  content change. It is lowered in place when the shape holds, and re-assembled otherwise. It
  walks only when `content_needs_walk` says so. hd-patch walks 8 of 122 transactions, down from
  111.
- **A latent G7a bug, fixed.** A transaction whose only `why` was CONTENT_SHAPE skipped the
  rows-only moves. Moves now run whenever no walk is needed. `walk-diff` catches the bug when it is
  reintroduced by hand (114 of 122 hd-patch mismatches).
- **Applier micro-optimizations.** IdHasher maps, a cull that writes each row as it visits it, a
  `StructKey::matches` without a children clone, an assemble that marks only the changed index
  span, and dirty ranges merged across small gaps.
- **On the phone, those cuts alone did not move the p95.** Non-step frames got much cheaper:
  hd-patch p50 went from 6.69 to 5.96 ms and apply p50 from 3.40 to 1.89 ms. The p95 went from
  13.0 to 13.5 ms. With less work per frame, the phone clocks down, and the untouched phases ran
  about 30 % slower. Only cheaper step transactions move the p95.
- **Payloads verified ahead of use** (above). hd-patch fetches 850 payloads in 122 transactions,
  mostly the animated mesh's surfaces, so this cuts every frame, not only the step transactions.
- **The web export's deferred digest** (above). The capi gains `rsc_set_digest_deferred` and
  `rsc_record_digest`, and the shim gains `set_digest_deferred` and `record_digest`. The capi test
  `deferred_record_digest_equals_inline` covers golden-6's `rate.rs6`.
- **Not done: the web export's payload path.** Its `provide` is a different code path: the capi
  hashes and copies the payload, and `plan.rs` decodes it at apply. Moving it means verifying in
  receiver.gd's fetch completion. That is the next bounded item, beside the step-transaction
  apply cuts. Both are in `results/gate7/g7o2.md`.
