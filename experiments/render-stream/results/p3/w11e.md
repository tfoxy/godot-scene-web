# W11e: the web export applies render-stream/11 (2026-10-27)

W11e makes the web export apply /11 ([protocol/render-stream-11.md](../../protocol/render-stream-11.md),
"As built (W11e)"). The web export is the receiver project on the pinned 4.5.1 `web_dlink_nothreads`
template, with the Rust core as a dlink side module (G7xw). /11 here includes W11t's live coding.
The web export runs the same `rs-core-capi` and shim as the native receiver, built for wasm, and the
same `receiver.gd`. W11d's capi work therefore reaches the web unchanged:

- bodies are ingested at accept;
- the retention rule runs in the core;
- `check_fetch`;
- region uploads;
- the coding decoder.

W11e opens the web export's own paths and proves them:

- **Live /11 on the web.** W11d's web guard on `RS_RECEIVER_PROTOCOL=11` is removed. The hello
  offers `render-stream.11` with `live_coding: zstd-base,zstd`, and every message is decoded in the
  side module before it is parsed.
- **WX's lazy store asks `check_fetch` before every GET.** On the web this is the only
  `inline-fetch-zero` gate in file mode. Without it, the `evict-carried` sabotage replays `ok`,
  because the store directory also holds the inline-sized payload.
- **The web half of g7-8 replays g8w11.** W11d's native checks judge the web export's replay of
  W11d's native legs (`@web`).
- **Two per-transaction GDScript loops are skipped when they do nothing**, at every version, with
  the same output.

**Results.**

- **Memory.** On STS2's /11 recording the web export's wasm heap peaks at **770 MB** with a summary
  log, against WX's 769 MB at /10. It peaks at 1,046 MB with a full log.
- **Fidelity.** Every scene's dB equals W11c's GSW to the hundredth.
- **STS2 combat live.** The web export applies **58.2 transactions a second**, against 6–15/s at
  /10. Its heap is flat (0.0 MB/min), and the host runs at 59.2 fps.

/8 to /10 are unchanged:

- the two GDScript cuts give the same output;
- the lazy-store call is gated on version 11;
- the adapter change only adds legs to the web half.

## Decisions

The rules are in the protocol doc's "As built (W11e)". In short:

1. **Same capi, same receiver.gd.** No web-only core code. The side module is W11d's capi built by
   `build-rs-core-web.sh`. Its `RscCoding`, `take_released` and `check_fetch` behave exactly as
   natively.
2. **`check_fetch` in WX's lazy store** (`_begin_store_fetch`), before each GET.
   - Natively the call sits in `_obtain_needed` (W11d). The web never reaches it in file mode,
     because the lazy GET has already put the payload in memory.
   - A dynamic surface names no hash, so `needed()` never lists one: the "payloads the dynamic
     bodies make unnecessary" are never fetched.
3. **WX's 64 KiB drop and the retention rule do not overlap.**
   - The drop forgets uploaded lazy-store payloads of 64 KiB or more.
   - The rule forgets hashes that left H. W11d's `release` also clears the drop mark.
   - Carried records are never marked droppable, so nothing in C leaves memory while in C.
4. **g8w11 joins g7-8's web half** (`GATE8_FILE_GROUPS`; out of `GSW_ONLY_SOURCE_GROUPS`) rather
   than getting its own web legs in gate 8. That is gate 7's established route for judging the web
   export with a gate's own checks. It gives exactly "the web leg of every W11d check".
   - A first prototype ran its own `gate8-w11-tool.ts web-legs` with web checks. It was dropped
     once W11d's native legs and checks existed, because it duplicated them.
5. **GDScript per-transaction cuts.**
   - Under `RS_RECEIVER_LOG=summary` the core's `mesh_uploads` rows are no longer visited. At /11
     there are two per dynamic mesh: STS2 combat has about 200 rows, capture-scale about 370.
   - `_note_applied` compares the resolved `unsupported` list with the previous one as a whole
     (`Array ==`, in C++). It rebuilds the per-entry keys, one `JSON.stringify` each, only when the
     list differs.
   - STS2 carries about 50 entries in every transaction. Natively that loop cost 76 µs per
     transaction against 3.6 µs for the compare (a headless micro-bench, 1,000 iterations).

They are replayed in the web export by g7-8's web half and judged by g8w11's own native checks
through G7b's view (`@web`).

**Sabotage of W11e's own call.** I removed the lazy store's `check_fetch` and replayed
`sabotage-evict-carried` on `scene/off`. The replay then ends `ok`: 300 of 300 transactions, 137
GETs, the inline-sized payloads served from the store directory. With the call, the same leg fails
`inline-fetch-zero` before any GET.

**Three gate 7 fixes the web half needed for g8w11** (`lib/gate7b-adapters.ts`):

- **Planned launches are not legs.** W11c's GSW legs write a native-shaped `env.txt`/`argv.txt` to
  `g8w11/gsw/<leg>/plan` that never runs natively. Discovery replayed them and then failed
  `applied-equals-native` ("applied.json missing on native"). A directory with neither
  `exit-code.txt` nor `applied.json` is now no leg. `self-test-gate7b.ts` has such a plan as a
  negative case.
- **/11 recordings resolve.** `compositor-equals-readback` resolves a leg's recording by its
  magic, and knew /8–/10 only: every honest g8w11 leg failed "recording does not resolve". It now
  takes /11. W11d's landing renamed the native legs' copies to `recording.rs<v>` and taught
  `legRecording` `.rs11`; `evidence-complete` failed on the earlier sink-named copies.
- **Memory-cache occupancy is policy, not state.** WX's lazy store forgets uploaded payloads of
  64 KiB or more that the native cache keeps, so the web's `w11.store_max_entries`,
  `store_max_excess`, `cache_released*` and each transaction's `w11.store_entries` differ from
  native's (scene: 5 against 9 entries). `applied-equals-native` drops exactly those keys
  (`dropMemoryCacheOccupancy`, self-tested); `native-store-bounded@web` judges the bound.

A prototype before W11d's native legs existed ran its own web legs on the same captures
(`gate8-w11-tool.ts web-legs`, nine web checks of the same properties): 9 of 9 passed. It was
dropped for the route above.

## Memory-worthy

- **A stale native `rs_core` GDExtension segfaults** a receiver whose GDScript calls a capi method it
  lacks; it does not error. Rebuild with `build-rs-core-ext.sh` after every capi change, and with
  `build-rs-core-web.sh` before `build-web-receiver.sh`.
- **`bench-live-scale.sh` holds two unbounded files.** On a long leg at /11 the host's hook log
  (`resources.jsonl`) grew about 1.3 GB a minute, and the tap's stream copy about 0.5 GB a minute.
  Pass `-- GRC_HOOK_LOG=off` for anything over a few minutes.
- **Godot `String` is UTF-32.** A 150 MB `applied.json` costs about 600 MB of heap while it is
  stringified. On the web, keep full-log evidence per transaction to digests, not hex dictionaries.
- WX's lazy store is the web's only file-mode origin read; any per-origin-read rule (here
  `inline-fetch-zero`) must sit in `_begin_store_fetch` as well as `_obtain_needed`.
