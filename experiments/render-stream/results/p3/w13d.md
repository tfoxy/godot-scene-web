# W13d: the native receiver and the web export accept render-stream/13 (2026-10-29)

W13d makes the native receiver (the stock 4.5.1 template with the Rust core through
`rs-core-capi`, `receiver/`) and the web export (the same receiver.gd and capi, built as the dlink
side module) accept render-stream/13 as W13a built it and W13b's capture emits it: /12 plus `GRSD`,
`predict_check` and the predicted `mesh_u8`/`mesh_f32`/`mm_f32` under /12's JSON meta (the binary
body stays on hold). A `GRSD` recording replays at /13 by its magic; live, `RS_RECEIVER_PROTOCOL=13`
offers `render-stream.13`. "As built (W13d): native and web" in
[render-stream-13.md](../../protocol/render-stream-13.md) is the spec of what was built. The planner
and the C++ shim are unchanged: they see /12's model.

## What changed

**rs-core-capi** (`src/core.rs`).

- `VERSIONS` gains 13.
- `ingest_dynamic` reads `Validator::record_view(record)` (W13a's note): at /13 the reconstructed
  /12 record that `dynamic_bodies()` and `multimesh_buffers()` index, else `record`. It is the
  only place the capi reads a transaction's blocks.
- `predict-check` hold: on a `predict-check` failure (`version >= 13`) the core sets
  `predict_await_full`; until a full transaction arrives `accept` returns the new kind `held`
  (`KIND_HELD`, 5) for every patch, without the validator, reading only its meta's canonical prefix
  (`peek_transaction`, GSW's W13c function). A session clears it.
- The receiver sabotage `no-predict-reset` (`W11Sabotage::no_predict_reset`): `Options` at the
  session, and rs-core's new `Validator::set_no_predict_reset` when the sabotage is named after the
  session (receiver.gd opens the core after the session record).
- `counters` gains `w13_predict_failures`, `w13_predict_dropped`, `w13_no_predict_reset` and
  `w13_history_units` (H1's bodies, AABBs and buffers) at /13.
- Tests (`tests/replay.rs`): `golden_13_applies_as_golden_12` (full, patch, inline and predict:
  the same RenderingServer call batches after every transaction as the /12 twin, and the same held
  dynamic bodies); `predict_check_holds_patches_until_the_full` (patch.rs13 with seq 12's
  `predict_check` corrupted: one `predict-check`, seqs 13 to 15 held, the full at 16 accepted after
  `transport_skip`, the stream ends on the unbroken replay's state; `no-predict-reset` fails at
  seq 16 and keeps failing); the ignored `accept_bench`.

**rs-core.** `Validator::set_no_predict_reset` (one setter).

**GDScript.** `rs_wire.gd` (`GRSD`, `MAGIC_V13_HEX`), `rs_live_client.gd` (`.13`,
`render-stream/13`), `rs_rust_applier.gd` (`no-predict-reset` in `CORE_SABOTAGES`,
`w13_counters()`), `receiver.gd`: file mode `GRSD` → /13; `RS_RECEIVER_PROTOCOL=13` natively and
on the web; the /12 hello under `render-stream/13`; live coding allowed at /13; a `predict-check`
error with a seq → `transport_skip` and `resync` (reason `coding`), a `held` record → no apply, no
ack; applied.json `w13` and `live.predict` (GSW's shape: the resyncs and the core's counters).

**Harness.**

- `gate8-w11-tool.ts`: W13c's /13 g8w11 legs lose `gswOnly`, so `native-plan` plans them for the
  native receiver; `native-plan --set pt13` plans g8pt's four headless /13 twin legs (frames in
  `g8pt/native-frames-pt13.json`, pump13's at g8mm's settle frames as for GSW).
- `run-gate8.sh`: `run_g8pt_native13` (the pt13 plan at `--fixed-fps 60` in its own 640x360
  gamescope, `g8pt/<capture's directory>/receiver`); `run_g8w11_receiver` takes extra receiver
  arguments; `run_g8w11c_native13` (g8w11c: `native13-honest`, `native13-predict-stale` and
  `native13-sabotage-no-predict-reset`, W13c's gsw13 legs for the native receiver, and for the
  web export under `GATE7_LIVE_KIND=web`; GSW keeps its gsw13 legs).
- `lib/gate8-w13-native-checks.ts` (new): the checks below, called from `runG8w11`, check-gate8.ts's
  g8pt block and `runG8w11cResync`. g7-8's web half discovers the new native file legs by itself
  (`GATE8_FILE_GROUPS` already holds g8w11 and g8pt) and judges them with these checks (`@web`).
- **Gate 7 for /13 legs** (found by the first local g7-8 web run): `wireVersionOf()` reads `GRSD`
  as 13 (W13a held it at 6 until a receiver accepted /13; `self-test-rs2.ts` asserts it), and
  `compositor-equals-readback` resolves /13 recordings; g8pt's `headless-pump` legs (gate8-mm's
  multimeshes, no GPU particles) are exempt from gate8-pt's approximate regions, so the band judges
  them as it does g8mm's; g8pt's `headless-shim` legs take no compositor screenshot (their emitters
  keep simulating after the last transaction).
- **W13b's transcode scratch** (`lib/gate8-w13-checks.ts`): `<g>/w13` is not writable when gate 7
  re-judges a cached source run (the cache keeps it read-only), so `w13-file-equiv`, `w13-equiv`
  and `w13-dyn-wire-catches-perturb-vertex` failed in every g7-8 view (`@web`, and
  `source-run-valid@web` with them) whenever the source came from the cache. The checks now fall
  back to a temporary directory, removed at exit.

## Deviations

- **g5c/g5e "reference exact"** is judged as mesh13 = the native /11 mesh leg at every shared frame
  (W11d's route for gate5-mesh at /11), not against a Godot reference rendered inside gate 8: gate 8
  renders no gate 5 reference, and the /11 leg's exactness chain (`native-w11-equals-v10`, gate 5's
  `reference` at the /10-equivalent path) is the established oracle.
- **`mm-reference` at /13** runs on g8pt's headless gate8-mm capture at /13 (W13b's
  `headless-pump13`), as W13c's GSW band does: g8mm's own captures are /11, which do not transcode
  to /13. The verdict is mm-reference's own (exact outside the known gaps), not a band.
- **The resync leg compares drawn state, and pixels only when they are comparable.** g8w11c's
  native receivers are headless (frame_post_draw never fires, so no shot), so
  `native13-predict-resync` compares the drawn dynamic bodies' digest at every frame both legs
  applied after the stale transaction (capture-scale's frames are deterministic, so two hosts agree
  frame by frame). A browser receiver at window 2 need not end on the same frame as its honest twin
  (the web run ended at 419 against 420): its final shot is compared only when the last frames
  match. The sabotage is caught either way (the receiver never catches up).
- **No live patch was held natively**: under window 1 nothing is in flight behind the failed
  transaction (`predict_dropped` 0). The hold path is covered by the capi test (three held) and
  by window-2 browser legs.

## For W13z

- Every receiver now accepts /13: GSW and the client (W13c), native and web (W13d). W13z switches
  couch-coop's seat (`GRC_STREAM_VERSION=13`) and the endpoint together.
- STS2 replay dB at /13 equal /12's on every receiver; nothing in the receivers needs to change
  for W13z's replay row.
- Native accept costs +29 µs a combat-heavy transaction (+21 %), wasm +49 µs (W13c): if the g31
  asks, the levers are W13c's (SIMD, a zero-copy history).

## Memory-worthy

- **The web export's STS2 menu is not frame-exact run to run** (±0.05 dB on the same /12
  recording, browser GPU particles); compare web menu dB with a band, map and combat exactly.
- **g8w11c is not in run-gate8.sh's DEFAULT_GROUPS**: a native gate 8 run (smoke or full) never

  half runs it for the browsers.
