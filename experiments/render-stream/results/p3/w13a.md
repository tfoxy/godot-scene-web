# W13a: render-stream/13 predicted blocks: codecs, goldens and validators (2026-10-29)

W13a builds render-stream/13 at the wire level, **staged** (render-stream-13.md "Staging"): the
predicted blocks of WB-D's design under /12's existing JSON meta, without the binary transaction
syntax, which is deferred to a separate increment judged on its own merit before the freeze.
"As built (W13a): the wire" in [render-stream-13.md](../../protocol/render-stream-13.md) is the
normative spec. Four implementations agree byte for byte:

- the reference codec, `protocol/golden-13/make_golden.py` (`to13`, `to12`);
- the C++ writer and its test reader (`capture/src/rs13_predict.{h,cpp}`);
- the TypeScript library (`scripts/lib/render-stream-2.ts` version 13);
- rs-core (`rs-core/src/predict.rs`, the validator's /13 accept path, `rs-core-check transcode`).

/13 is /12 plus the `GRSD` magic, the protocol string `render-stream/13`, a transaction key
`predict_check` (XXH64 of the reconstructed `mesh_f32` ‖ `mesh_u8` ‖ `mm_f32`, 16 lowercase hex
digits, right before `blocks`), and those three blocks coded as residuals against the stream's two
previous transactions. Nothing emits or receives /13 yet: the capture's sinks and listener are
W13b, the receivers W13c (GSW) and W13d (native and web). Every /2 to /12 path is unchanged.

**Measured on `pm7-a12-1`** (the newest STS2 recording, /12, 281 MB), transcoded by
`rs-core-check transcode` and measured with `wire-budget.py measure` (base-prefix zstd-3 per warm
patch, W11t's coding; + 28 B of W11t envelope and checksum to compare with WB-D's table):

| scene (warm patches) | /12 coded | **/13 as built, coded** | WB-D prototype `json_w13` | WB-D `w13` (binary) |
| -------------------- | --------: | ----------------------: | ------------------------: | ------------------: |
| combat (2,713) | 13,313 | **6,424** (3.08 Mbps) | 6,412 | 6,171 |
| map (716) | 324 | **324** | 324 | 332 |
| menu (1,425; incl. resource records) | 2,024 | **1,514** | 591 + 324 records | 510 + 324 |

Combat lands within 0.2 % of the prototype (the 35-byte `predict_check` costs about 17 B coded,
being random hex; the prototype's raw units were coded from 0.0, as built they travel as
themselves). The menu column here counts the resource records' framing as the transaction message
does in `measure` (raw, not coded), so it reads higher than WB-D's split; /13 saves 510 B a frame
there (`json_w13`: 529).
Raw, /13 is /12 plus 35 B a transaction (pm7-a12-1: 281,058,616 → 281,232,041 B): prediction
pays only under zstd. 99.9 % of the recording's predicted units are second order.

## Decisions

The staging left choices to make. Each is in "As built (W13a)" and was decided for the frozen wire:

1. **Where the check lives.** Under the JSON meta the 8-byte binary `check` becomes a key,
   `predict_check`, on every transaction (fulls too: one rule, and a full's check still catches a
   corrupt block), as 16 lowercase hex digits (a u64 cannot be a JSON integer under /0's 2^53
   rule). A framing field would have touched every framing parser; the key touches only the schema.
2. **History is resolved state, not "last sent".** H1 and H2 are the prediction state after T−1
   and T−2, with every unit T−1 did not carry kept at its value. A mesh that pauses is then
   predicted with zero motion (the prototype extrapolated its last motion). `predict.rs13` seq 6
   is that case.
3. **Raw units travel as themselves** (the design's text), not as residuals against 0.0 (the
   prototype's arithmetic). Fulls use the same layout (streams, transposes) with every unit raw:
   one code path.
4. **Pass-through.** A block whose /12 offset rule fails is carried untransformed, so a malformed
   stream fails with /12's code (`mesh-u8-offset`, `payload-size`, `mesh-offset`, `mm-offset`)
   rather than with a garbled prediction. Four `pass-*` vectors prove it.
5. **Check order:** framing, meta (with `predict_check`), un-predict, `predict-check`, every /12 rule
   on the reconstructed record, then the history advances. A failed transaction changes nothing.
6. **The decoded form** keeps metas verbatim (`predict_check` included) and shows the
   reconstructed blocks; the resolved form is /12's content (`render-stream-13-{decoded,resolved}/1`).
7. **Transcode** /12 ↔ /13 moves the end record's `bytes_total` by the size change and keeps
   `max_record_bytes` the file's own, so /12 → /13 → /12 is byte-identical even for a vector whose
   stats were wrong on purpose. Only /12 transcodes: a /11 recording would need the six /12 session
   fields invented.
8. **No `rs-core-capi` VERSIONS 13.** The W13a row listed it, but the capi offers what the receiver
   applies; that is W13d's ("capi at /13"). rs-core's API for it is ready (below).

## What changed

**Goldens** (`protocol/golden-13/`, `make_golden.py --check`: 55 outputs). The generator loads
golden-12's and transcodes its recordings; it is the reference codec.

- `full.rs13`, `patch.rs13`, `inline.rs13`: golden-12's three recordings at /13 (`.hex`,
  `.decoded.json`; `resolved.json` is golden-12's states).
- **The prediction lane** `predict.rs13` (and its /12 twin `predict.rs12`, `predict-resolved.json`):
  ten states, seqs 1 and 7 full. A dynamic quad (raw, first order, second order with an all-zero
  position residual, a shape change back to raw, first order, second order), a skinned triangle
  with a quiet NaN, a payload NaN and −0.0 in predicted words, a pause (zero-motion prediction),
  removal; AABBs at constant velocity inside a binade (all-zero second-order residuals); a vertex
  coordinate moving 1.25, 1.5, 1.75, 2.0, 2.25 across the binade at 2.0 (linear in value, not in
  bit pattern) and another crossing zero; multimesh 1's instance count changing (raw); multimesh 2
  new after the mid-lane full. `index.json` `predict_trace` lists every unit and its order.
- **38 invalid vectors**, each failing one rule at a known seq: `predict-check` four ways (a flipped
  residual bit in `mesh_u8`, `mesh_f32`, `mm_f32`, and in a raw unit of a full), `predict-stale`
  (the encoder sabotage's output), `meta-schema` three ways (`predict_check` missing, uppercase,
  15 digits), the four `pass-*` vectors, `bad-magic` (golden-12's `full.rs12`), and golden-12's 25
  /12 invalid vectors transcoded, each keeping its /12 code. Plus `corrupt-meta.rs13`.

**C++** (`capture/`). `ProtocolVersion::V13` (magic, protocol, every "/12 or later" cascade:
45 lines in existing files). `rs13_predict.{h,cpp}`: `rs13::Predictor`, a per-stream history
(ref-counted body buffers) that codes a /12 transaction record into its /13 record
(`encode`, `encode_transaction`) and back (`decode`), with `predict_stale`, `no_reset` and a unit
trace. `test/rs13_codec_test.cpp` (ctest `rs13_codec`): golden-12's 26 states written at V13 are
`full/patch/inline.rs13` record for record; the prediction lane's ten states built in C++ are
`predict.rs12` at V12 and `predict.rs13` at V13 (trace included); the stale writer is
`invalid/predict-stale.rs13`; the reader round-trips every lane and golden-12 invalid vector,
rejects the vectors with their code and seq; XXH64 vectors.

**TypeScript** (`scripts/lib/render-stream-2.ts`, `scripts/test/self-test-rs2.ts`). `version` 13,
`MAGIC_V13`, `predict_check` in the schema and canonical check; the validator, `decodeRecording`
and `resolveRecording` un-predict before every /12 rule. Exports `encodeRs13(data12, {stale,
trace})`, `decodeRs13(data13, {noPredictReset})`, `createRs13Unpredictor`, `xxh64`/`xxh64Hex`,
the validator option `noPredictReset`. `runSuite(golden-13, 13)` and the transcode, trace, stale
and sabotage checks: 1,684 self-test checks (198 new for golden-13), all pass.

**Rust** (`rs-core/`).

- `predict.rs`: the history (shared entries; R(T) reuses H2's allocations, so a steady stream does
  not allocate), the block coder, `unpredict_record`, `to13`/`to12`, the trace. `predict_tests.rs`:
  the property test (24 seeds × 120 transactions with random shapes, shape changes, pauses,
  removals, instance-count changes, fulls and pass-through; decode(encode) = input and both ends'
  histories equal after every transaction), special words (NaNs, ±0, infinities, subnormals,
  binade crossings) at every order, XXH64 vectors, refusal of invalid inputs, and an ignored bench.
- The validator: `predict_check` in `meta.rs` and the fast path, the /13 accept path, option
  `no_predict_reset`. **For receivers:** `Validator::plain_record()` is the accepted /13
  transaction's equivalent /12 record (exactly `to12`'s), `record_view(record)` returns it at /13
  and `record` otherwise; `dynamic_bodies()` and `multimesh_buffers()` index the plain record.
  `PayloadStore::accept_transaction` already uses `record_view`. Record digests and end-record
  stats stay over the /13 bytes.
- `goldens.rs`: golden-13 (199 checks) and the 12↔13 `bad-magic` pairs; `--sabotage
  no-predict-reset`. `rs-core-check transcode --to 12|13 [--stale] <in> <out>` and
  `transcode --roundtrip <file.rs12>...` (sizes and units by order); `validate` reads /13.
- `rs-core-capi/src/core.rs` and `web/gsw-rs/src/lib.rs`: one line each for the new option.

**Cost** (`rs-core-check bench`, `Validator::accept` per transaction, pm7-a12-1, under
`quiet.sh exclusive`, load 2.2): /12 p50 62.2 µs, p95 72.3; /13 p50 89.8, p95 101.3. The /13 extra
is 27 µs (13 un-predicting the blocks, 5 advancing the history, 2.7 the XXH64, 2 the plain record),
inside the design's 15–30 µs projection. The first implementation took 73 µs; the rewrite decodes
straight from the streams into the plain record, four words at a time, with no per-surface
allocation.

## Validation

- **Unit level, in the worktree:** `make_golden.py --check` for golden-13 (55 outputs) and every
  earlier golden; `self-test-rs2.ts` 1,684/1,684; rs-core `cargo test --release` 116 pass
  (2 ignored benches); `rs-core-check goldens` all pass (golden-13 199/199, cross-version 20/20,
  golden-2 to golden-12 at their previous counts); `--sabotage no-predict-reset` fails only
  golden-13 (180/191: `predict.rs13` at seq 7, `patch.rs13` at 16, the full lanes at 12); capture
  ctest 43/43 (`rs13_codec` new); rs-core-capi tests pass; `build-rs-core-ext.sh` builds; `tsc`
  shows only the 8 baseline errors.
- **Cross-implementation agreement:** each implementation matches the generator's bytes on every
  golden, both directions: C++ (writer from states, and record-level transcoder), TypeScript
  (`encodeRs13`/`decodeRs13`), rs-core (`to13`/`to12`), and each reproduces
  `invalid/predict-stale.rs13` and the `predict_trace` unit lists.
- **Sabotages:** `predict-stale` (C++ `Predictor::predict_stale`, TS `stale`, rs-core `--stale`)
  writes `invalid/predict-stale.rs13`, which every validator rejects with `predict-check` at seq 2;
  `no-predict-reset` (rs-core `--sabotage`, TS `noPredictReset`, C++ `no_reset`) fails
  `predict-check` at `predict.rs13` seq 7 and `patch.rs13` seq 16.
- **Kept recording:** `pm7-a12-1` (the only kept /12 one; the others are /8 and /11) round-trips
  /12 → /13 → /12 byte-identical through rs-core, and /13 → /12 → /13 likewise.
- **Smoke and remote:** see "Validation runs" below.

## Deviations

- **Binary syntax, `schema.json` and the `binary-*` vectors:** deferred by the staging decision.
- **Kept recordings:** one (/12) instead of GSI's 13; /11 and /8 recordings have no lossless /13
  mapping (decision 7).
- **No capi `VERSIONS` 13** (decision 8).
- **Implementation was split** between three parallel agents (C++, TypeScript, Rust) against the
  golden written first, plus one optimization pass on the Rust un-predict path. Every
  implementation matched the generator on its first full run.

## For W13b, W13c and W13d

- **W13b (capture).** Keep one `rs13::Predictor` per /13 connection and per file sink; feed it every
  transaction record in send order (`encode`); a full resets it by itself. It works on the /12
  record bytes, so formation is "encode /12, then `encode`" (it re-parses its own meta: cheap to
  start, a typed path later if the profile asks). The shared-encode memo key gains T−2's state.
  `GRC_STREAM_VERSION=13` and the listener's offer are not wired; `is_v12_or_later` already includes
  V13, but explicit `== V12` tables (listener, hello) do not.
- **W13c / W13d (receivers).** Call rs-core's validator as now; at /13, pass
  `v.record_view(record)` where `record` goes to `dynamic.ingest` / `multimeshes.ingest`
  (rs-core-capi `core.rs` about lines 497–521, gsw-rs `lib.rs` about 1280–1315), add 13 to the capi
  `VERSIONS` and the hello. A `predict-check` failure must resync with reason `coding` (W11t's
  path). TypeScript's `decodeRecord()` alone is stateless and leaves the three blocks coded: a /13
  checker reading raw blocks must go through `createRs13Unpredictor` (or `decodeRs13`), and
  `wireVersionOf()` still maps `GRSD` to 6 until a receiver accepts /13. The BigInt XXH64 runs at
  about 55 MB/s; a TS receiver path would want a two-u32 version.
- **Receiver cost:** +27 µs native per combat transaction (above); W13c measures wasm.
