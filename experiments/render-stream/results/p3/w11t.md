# W11t: base-prefix zstd as the /11 live transport coding (2026-10-27)

A /11 live connection whose hello offers `live_coding` now receives every message zstd-coded,
each patch against its base transaction's uncoded message as a raw prefix. The host encodes with its
vendored zstd 1.5.7. The receivers decode in rs-core with the pure-Rust `ruzstd`.

Warm STS2 combat through the capture's real encoder comes to **12,506 B a frame (6.0 Mbps)**, records
included. WB and W11b predicted 12.5 KB. The host encodes it in **0.19 ms**, and rs-core decodes
it in **0.10 ms natively and 0.12 ms in wasm**.

The spec is [protocol/render-stream-11.md](../../protocol/render-stream-11.md), "Transport:
base-prefix zstd" and "As built (W11t): decisions".

## The dependency

- **ruzstd 0.9.1**, published 2026-10-11 (16 days old at the pin).
  - License: MIT. The crate's LICENSE reads "Copyright (c) 2019 Moritz Borcherding". The repo is
    https://github.com/KillingSpark/zstd-rs.
  - Compatible: this repository is MIT too, and it ships the crate only as a build-time dependency
    (the registry's copy, not vendored).
  - Checksum (sha256 of `ruzstd-0.9.1.crate`, on crates.io and in the lockfiles):
    `69e4ce4a039f42bf25920b95667e4d789e98749ab11bbb8d2c2936f788421bb5`.
  - Pinned `=0.9.1` with `default-features = false` and `features = ["std"]`, so it pulls in no
    other crate. The default `hash` feature would have pulled in `twox-hash`, so rs-core computes
    the XXH64 checksum itself.
  - Cargo.lock in rs-core, rs-core-capi and web/gsw-rs gains only this entry.
  - Provenance: `artifacts/render-stream/p3/w11t/ruzstd-provenance.txt`.
- **Prefix support.** ruzstd decodes libzstd `refPrefix` frames byte-exactly, but it has no
  public raw-content constructor (its scratch types are private).
  - The workaround is a 117-byte formatted template dictionary, with entropy tables from zstd
    1.5.7's trainer, repeat offsets 1, 4, 8 and no content. Each base is decoded as this template
    with `dict_content` set to the base, forced onto the frame (`force_dict`).
  - A `refPrefix` frame starts with no entropy repeat state, so the template's tables are never
    read.
  - Proven first on 16 real STS2 pairs (menu, map and combat, coded by Python's binding of zstd
    1.5.7), then on everything below.
- **wasm cost.** The decoder alone in a minimal wasm32 cdylib is 116 KB. That is an upper bound:
  it includes std formatting, which rs-gsw-wasm already links.

## Decisions

All twelve are in render-stream-11.md, "As built (W11t)". In short:

1. **No acceptance field.** Every message of a coded connection is coded, the session message
   included. The receiver learns the host's answer from its first message's magic. The record
   stream and its validators do not change.
2. **The envelope.** A coded transaction is a zstd skippable frame (magic `0x184D2A5B`, holding
   `seq` and `base_seq`), then one frame.
   - The envelope picks the prefix before decoding, and names the seq to resync when decoding
     fails.
   - A coded message stays a valid zstd stream: `zstd -d --patch-from=<base>` decodes it.
   - Records, the session message and the end record are one frame with no envelope.
3. **Checksum.** Every frame carries its content size and an XXH64 checksum. A wrong prefix is
   then `coding` at the transport, not garbage at the parser.
4. **The base** is the last transaction formed on the connection, a dropped one included.
5. **Retention.** The receiver keeps the newest transaction and its base, two messages at any
   window, capped at three.
6. **Resync.** On a `coding` error the decoder skips based transactions until a full one, and the
   receiver sends `resync` with reason `coding`.
7. **The hello.** `live_coding` is optional, /11 only, and the only optional control key. A
   receiver from before W11t therefore stays valid and uncoded.
8. **Sharing.** Coded transactions are memoized per callback by their uncoded base and target
   messages, seqs included. Lockstep viewers with equal seqs share the compressed bytes. Viewers
   at different seq offsets cannot, because the stamps differ.

## What W11c, W11d and W11e must call

Each receiver makes one call on every WebSocket message, before it parses the message:

- **GSW** (W11c): `const n = coding.decode_rx(g, len)`, with
  `coding = new LiveCoding(offer, inbound_buffer_bytes)`.
  - It decodes in place in the rx buffer, ahead of `live_session` / `live_accept`.
  - It returns `n > 0` (the uncoded length), `0` (skipped: no apply and no ack) or `-1`
    (`coding.error()`).
- **Native and web export** (W11d, W11e): `rsc_coding_decode(h, data, len, &out, &out_len)`
  before `rsc_session` / `rsc_accept`, with `h = rsc_coding_new(offer, len, inbound)`.
  - It returns `1` (decoded), `2` (uncoded: `out` = `data`), `0` (skipped) or `-1`.
  - It still needs a binding in the shim (`receiver/ext/rs_core_ext.cpp`).
- **With either call:**
  - the hello adds `"live_coding": "zstd-base,zstd"`;
  - on `-1` with a non-zero `seq()` / `rsc_coding_seq`, send
    `{"type":"resync","stream_id":…,"seq":…,"reason":"coding"}`;
  - on `-1` with seq 0, fail the stream.

At landing, no receiver speaks /11 live yet: W11c had not landed, and W11d and W11e are to come.
The live proof therefore runs on the Node viewer, which uses the same wasm decoder and the same
resync rule.

## Deviations

- **No receiver applies a coded stream yet.** No receiver speaks /11 live at landing, so the
  live legs prove decode, losslessness and resync on a Node viewer that uses rs-core's wasm
  decoder.
  - "Applies identically to off" is shown as equal resolved state per frame (TypeScript resolver)
    against an uncoded viewer of the same host, plus byte-equal decoded streams.
  - Pixels wait for W11c's GSW wiring.
- **The shared-encode proof is the unit test.** Live viewers rarely join in one callback, so
  `coding-shared` is informative (0 in this run).
- **Additions to the frame.** The checksum and the envelope are additions to "one zstd frame at
  level 3 with content size". They cost 28 B a transaction, for wrong-prefix detection and resync
  without decoding.
- **Rough timings.** The encode and decode figures are minima of 3 passes on a loaded desktop, not
  timing legs. A real-time comparison belongs to the sweep.

## Memory-worthy

- ruzstd 0.9.1 decodes libzstd `refPrefix` frames but has no raw-content constructor.
  - `Dictionary`'s fields are public but its scratch types are private.
  - So parse a formatted template once with `decode_dict`, set `dict_content` and
    `offset_hist = [1,4,8]`, then call `add_dict` + `init` + `force_dict`. `decode_all` cannot be
    used, because `force_dict` must come after `init`.
- A wrong-prefix sabotage must shift the prefix (append a byte), not flip one. zstd copies only
  bytes the target shares with the prefix, so a flipped byte is often never read, and the flipped
  receiver sabotage decoded golden-11's patch stream correctly.
- A coded transaction's bytes depend on both messages' seq stamps. Lockstep viewers share coded
  bytes only when their seqs are equal, which viewers joining at different callbacks never are.
- Live viewers launched together through `mise exec pnpm exec tsx` still join at different host
  callbacks.
