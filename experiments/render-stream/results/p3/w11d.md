# W11d: the native receiver applies render-stream/11 (2026-10-27)

W11d makes the native receiver (the stock 4.5.1 template with the Rust core through `rs-core-capi`,
`receiver/`) apply /11 ([protocol/render-stream-11.md](../../protocol/render-stream-11.md), "As
built (W11d)"), with W11c's rs-core receiver API and W11t's live coding:

- `GRSB` recordings replay at /11, and `RS_RECEIVER_PROTOCOL=11` offers `render-stream.11` live;
- dynamic mesh bodies are ingested at accept, by mesh id, inside the capi, and drawn with region
  uploads (`mesh_surface_update_vertex_region`/`_attribute_region`) on the mesh's own RID;
- the retention rule runs in the capi after every accept and apply, and the receiver's memory cache
  (`RsResourceCache`) forgets every hash it drops;
- `inline-fetch-zero` is asked before every origin read (the store directory, or an HTTP GET);
- live, the hello offers `live_coding: zstd-base,zstd`, every message is decoded in the capi before
  it is parsed, and a `coding` error resyncs. That needed one rs-core addition,
  `Validator::transport_skip` (decision 1): before it, no receiver could validate the full
  transaction a coding resync forces.

/8 to /10 are untouched: every new path is gated on version 11 (the validator's skip state is only
ever set by a /11 coding error, `released()` and `dynamic_bodies()` are empty below /11, and the new
evidence keys are written at /11 only).

## Decisions

The rules are the protocol doc's "As built (W11d)". In short:

1. **`Validator::transport_skip`.** After a `coding` error the decoder skips every based
   transaction until the full one, so the validator never sees them. The full then arrives with a
   seq gap; the host computed its records against a base the receiver never decoded (so it may
   re-carry a hash already in the receiver's C); and the records before a skipped transaction may be
   named by nothing the validator sees. After `transport_skip`, the next transaction must be full and
   may jump seqs, `resource-duplicate` and `resource-unnamed` are relaxed for that window, and C is
   pruned to names(S) whole once the full is accepted, which makes C = inline(S) again (L1 holds from
   there). The end record's count includes the skipped transactions; its byte stats are not checked
   after a skip. GSW (W11c) does not call it yet, so a GSW coding resync would still end in `seq-gap`
   (W11c's live legs never needed one).
2. **Bodies at accept, in the capi** (`Core::dynamic`, W11c's `DynamicMeshes`), before receiver.gd
   reuses the message buffer. receiver.gd never handles a body.
3. **Region uploads on the same RID.** `create` when not resident; `rebuild` (`mesh_clear` plus
   `mesh_add_surface`) when the mesh was built from hashed surfaces, or a surface's layout or a moved
   body's index bytes changed; otherwise one `update` per moved surface: vertex and attribute
   regions (skin when present) at offset 0. Two refinements of W11c's rule: the layout includes the
   body's AABB and uv_scale (a region upload keeps Godot's old surface AABB, and the canvas culls a
   mesh by `mesh_get_aabb`); and a mesh turning dynamic is rebuilt in place, not freed and created,
   since nothing replays the items drawing it.
4. **The store is `RsResourceCache`.** rs-core gained `Retention::sweep_with` (a store-agnostic
   sweep; `sweep` calls it). The capi sweeps with the planner's resident hashes as the display,
   drops its own staged copies, and hands the hashes back (`take_released`); receiver.gd drains them
   after each accept and apply and calls `RsResourceCache.release` (no per-hash memory of a drop is
   kept). Disk-cache files stay.
5. **Live coding in the shim.** The `RsCore` instance owns one `RscCoding` per connection
   (`coding_open` at each hello). 1 → the decoded bytes, 2 → the message as is, 0 → dropped (no
   accept, no ack), -1 with a seq → `transport_skip` + `resync` (reason `coding`), -1 with seq 0 →
   the stream fails. `received.rs11` holds the decoded messages.
6. **Evidence in GSW's names.** applied.json `w11` (bounded) uses W11c's `gsw.w11` keys, and a full
   log's transactions carry GSW's `dynamic_sha256` digest, computed the same way, so one checker
   judges either receiver (gate 7's GSW half reads GSW's `perf.json` for the same keys).
7. **Sabotages**: W11c's names. `stale-dynamic-rx`, `no-prune`, `ignore-released` in the capi;
   `evict-carried` in receiver.gd.

### The optional live leg: not run

At /10 the native receiver managed 6–15 combat updates a second live because every pose was its own
resource record handled in GDScript. At /11 a combat transaction is one message (`records-per-tx`,
and 0 pose records in the STS2 recording), and the native core spends about 1.9 ms on it (above), so
the per-record bottleneck is gone and the 60 Hz host bounds the rate. I did not run the 5-minute game
leg: W11c's farm (`w11c-root`) is gone, so it would have needed a new farm and a native live hook for
the C3 harness (`rx-gsw-live.sh` is GSW's), for a number the replay already bounds. W11z's acceptance
leg measures it live. No game was launched, so no game process exists.

## Deviations

- **No `RsResourceCache` "drop on leave" from the planner's maps.** The design names "capi maps
  prune". The capi has no hash maps beyond its staged and provided payloads (both now drop released
  hashes); the planner's resident meshes hold their own surface copies, which go with the mesh.
- **`store-bounded`'s RSS slope** is judged on the STS2 replay (flat over combat under the summary
  log), not a 20-minute capture-scale live leg; the cache entries are judged on every g8w11 leg.
- **g5c and g5e `reference` at /11** are judged as `native-w11-equals-v10` on gate5-mesh (the /11
  shots equal the /10 path's, which gate 5 judges against Godot), as W11c did for GSW.
- **The web half of g7-8 skips g8w11** until W11e (`GSW_ONLY_SOURCE_GROUPS`).
- **The live game leg** was not run (above).

## For W11e and W11z

- The web export reaches all of this through the same capi and shim; `receiver.gd` refuses
  `RS_RECEIVER_PROTOCOL=11` on the web only by an explicit guard in `_parse_wire_env`, and g7-8's
  web half by `GSW_ONLY_SOURCE_GROUPS`'s `g8w11` entry. Remove both when the web export applies /11.
- GSW should call `Validator::transport_skip` on a coding error (W11c's `codingResync`), or its
  first coding resync fails `seq-gap`.

## Memory-worthy

- A /11 coding resync cannot be validated without telling the validator: the full arrives with a
  seq gap, and the host's records were computed against a base the receiver never decoded.
  `Validator::transport_skip` is the fix; GSW lacks it.
- Editing a runner script while it runs breaks bash at the next unparsed line (`syntax error near
  unexpected token`): bash reads the file as it goes. Run edited runners from a copy, or not at all
  until the run ends.
- A live native receiver needs `RS_RECEIVER_MODE=live`; without it, it falls back to file mode and
  fails `recording-unreadable`.
- A headless native receiver runs live fine (credit stage `applied`), so live coding legs need no
  gamescope.
- STS2 spine meshes set their custom AABB every frame: a combat transaction is about 102 region
  updates and 102 `mesh_set_custom_aabb` calls.
