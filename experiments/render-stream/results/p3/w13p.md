# W13p: render-stream/13 prediction made cheap on the host and the receivers (2026-10-30)

W13p cuts what /13's prediction added to formation on the capture (W13b) and to accept on the
receivers (W13c, W13d), with the wire byte-identical. "As built (W13p): cost" in
[render-stream-13.md](../../protocol/render-stream-13.md) says what was built.

## What changed

**Capture** (`capture/src/rs13_predict.{h,cpp}`, `rs_live.{h,cpp}`).

- `rs13::PredictMeta`: the meta keys the predictor reads, typed. `rs13::predict_meta(transaction)`
  builds it from the `rs2::Transaction` with `encode_transaction`'s own offset rules (`u8`, `f`,
  `aabb_f`, `buffer_f` running offsets, the held bodies and buffers, dynamic surfaces' null
  hashes and body lengths, /11+'s block names). A bare record's JSON is converted to the same
  struct keeping make_golden.py's distinctions (a number that is an int, a float, null or another
  value; a list that is an array, missing or another value), so the reader, `encode(record)` and
  `encode(meta, record)` code every record alike.
- `Predictor::encode(const PredictMeta &, record)` (and `encode(transaction, record)`): no JSON
  read. `rs13::encode_transaction()` (the file lanes) uses it; the live hub keeps the typed meta on
  `SharedTx` (`predict`, built once per formed /12 transaction, shared with the connections that
  re-stamp it) and passes it to `form_predicted` (the honest and the `predict-stale` coding).
- Coding writes the /13 record directly: the meta with `predict_check` spliced in, every block in
  place, `mesh_u8` coded straight from each body into the streams (`for_each_part`: each word
  scattered to its byte planes, colour and UV de-interleaved in place, the residual templated on
  the unit's order), `mesh_f32` and `mm_f32` transposed raw and then overwritten with the units'
  residual words. `predict_check` is a streaming XXH64 over the three /12 blocks (no
  concatenation). Layouts, the decoded blocks (reader) and the hash state live in per-predictor
  scratch (`Predictor::Scratch`; copies share H1/H2 and never the scratch).
- History: R(T) reuses the state that leaves the history (H2) when the predictor is its only
  holder (`next_state`): its map nodes take R(T−1)'s copy, its bodies and buffers no one else holds
  go to a byte-vector pool that T's units refill. Live predictors whose states a memo entry still
  holds simply allocate, as before.
- `rs13::set_verify_meta(true)` (set by `rs_publish_test` and `rs_live_test`): every typed encode
  also parses the record's JSON and aborts unless both metas agree. A mutation of
  `predict_meta()`'s `buffer_f` is caught by both tests, of the dynamic surfaces' `hash` by
  `rs_live_test`.

**Receivers** (`rs-core/src/{predict,validate,payload,predict_tests}.rs`, the wasm build).

- History in fixed per-unit slots (each unit's last two values; an id-indexed array below 65536,
  a map above), touched only for the units a transaction carries or drops: no per-transaction
  clone of the state, no allocation in steady state.
- The validator's path (`take_plain`, `accept_plain`, `return_plain`) keeps its last few plain
  records in the history and reads H1/H2 bodies where they sit; a recycled record first copies out
  the bodies of units still reading it (units no longer carried).
- `predict::lanes`: four 32-bit lanes, wasm `simd128`, SSE2 on x86-64, plain words elsewhere, for
  the byte-plane untranspose (16 words a step), the un-residual, the colour/UV attribute section
  and the index/skin XOR; unit tests check each against the scalar path.
- `payload::expected_mesh_buffer_bytes`: a 64-bit fast path below 2^31 (wasm has no native 128-bit
  multiply).
- `web/gsw-rs/.cargo/config.toml`: `+simd128` for rs-gsw-wasm, read by `build-rs-core.sh` and the
  live client's `build-web.sh` (both now run cargo from the crate's directory, or cargo ignores
  that file). The web export's emscripten side module (`build-rs-core-web.sh`) does not get SIMD:
  whether the 4.5.1 web template loads a side module with SIMD instructions was not established,
  so it takes the plain-word lanes. The default rs-gsw-wasm bytes change (2,430,648 →
  2,418,563 B).

## Host cost

**Formation on the capture** (`bench-capture-scale.sh --mode file`, capture-scale full size, 600
frames, `GRC_STREAM_VERSION` 12 or 13; main is `adf97029` built from `git archive` in the
scratchpad). Instructions: the armed leg under `--perf` with HC2's
`RS_BENCH_PERF_ARGS="-e instructions -c 1000000"`, inclusive samples of the patch lane's
`Publisher::write_transaction` (the file-lane formation, on HC5's writer thread) per transaction.
Real time: the end record's `encode_ns_total` per transaction, the legs real-time under the
exclusive quiet lock.

| per transaction | main /12 | main /13 | W13p /13 |
| --- | --: | --: | --: |
| formation, M instructions | 3.02 | 4.55 | **3.26** |
| of which `rs2::encode_transaction` (the /12 record) | 2.91 | 2.96 | 2.93 |
| of which the predictor | — | 1.35 (`Predictor::code`) | **0.23** (`Predictor::encode`, `predict_meta` 0.002) |
| formation, real time (`encode_ns_total` / tx) | 390 µs | 894 µs | **505 µs** |
| W13p's own /12, real time | | | 320 µs |
| formation, M cycles (W13p /12: 1.60) | | | **2.01** |

/13 formation is now **1.08× /12's in instructions** (was 1.51×): the predictor's irreducible part
(coding every predicted word, the hash, the history) is 0.23 M instructions on top of /12's 3.02.
In real time this host's runs are noisier than the instruction counts (other repos' load outside
the lock; /12 alone read 390 and 320 µs in two runs); W13p's /13 read 505 µs against 320 to 390 for
/12 (1.29× to 1.58×), where main's read 894 (2.3×). Two more
real-time pairs (W13p only): /12 410 and 326 µs, /13 950 (that leg's snapshot ran at 3.7 ms a
frame against 0.76 normally: machine contention) and 489 µs.

Cycles (the same `--perf` leg with `-e cycles -c 1000000`) explain the wall time better than the
instructions: W13p's formation is **2.01 M cycles a transaction at /13 against 1.60 at /12
(1.26×)**: `rs2::encode_transaction` 1.11 (1.19 at /12), the predictor 0.43 (`encode_typed`
0.36, of it writing the 160 KB record and the predicted words; `next_state` 0.10, R(T−1)'s map
copy; `predict_meta` 0.005), the rest the lane's write. That is inside the brief's ~1.3× target;
what remains is per-word coding and one fresh record buffer a transaction (the next lever:
recycle the dropped /12 record as the next /13 output buffer).

**The predictor alone** (`Predictor::encode` over a /12 recording's records, a scratchpad bench
linked against main's or this tree's `rs13_predict.cpp`, -O2 as the capture builds, minimum of 3
repeats per record; instructions from `perf_event_open` around each call), pm7-a12-1's 4,954
patches:

| per patch | main (`encode(record)`) | W13p `encode(record)` | **W13p `encode(meta, record)`** |
| --- | --: | --: | --: |
| M instructions p50 / mean | 5.19 / 3.27 | 3.04 / 1.94 | **0.88 / 0.53** |
| µs p50 / p95 / mean | 382.6 / 393.5 / 240.4 | 226.8 / 256.4 / 151.0 | **70.2 / 72.6 / 43.4** |

The typed path is what the capture runs; `encode(record)` (the bare record, still parsing its JSON)
is kept for tools and tests and got the coding and history savings only.

## Receivers

wasm (`profile-rs-core-wasm.mjs`, rs-core's `prof::replay` in Node, every timer's minimum over 5
repeats, `quiet.sh exclusive`), pm7-a12-1 and its /13 transcode, `accept_us` per transaction:

| | /12 p50 / p95 / mean | /13 p50 / p95 / mean | /13 over /12 (p50) | load |
| --- | --- | --- | --: | --: |
| before (main's core, this host today) | 212.4 / 221.4 / 141.5 | 261.6 / 273.1 / 172.5 | +49.2 µs, **+23.2 %** | 6.2 |
| W13p | 211.0 / 219.1 / 140.6 | 239.4 / 253.2 / 159.9 | +28.4 µs, **+13.4 %** | 0.6–2.6 |

`pre_checks` at /13 (un-predict, check, plain record) 41.6 → 24.8 µs. An instrumented build (timers
since removed) split the remaining /13 extra into un-predict 14.7 µs (was 33.5), history 4.7 (was
9.2), XXH64 3.0 (2.9) and about 3.4 for the plain record and the rest. In steps: `+simd128` alone
took accept to +15.5 %; the lane kernels and the id-indexed slots to +13.3 %; the retained plain
records to +13.2 % (about 1 µs: copying bodies was not the cost).

**The design's +10 % on wasm accept is still missed** (+13.4 %, 6.7 µs over the bar). What is
left is per-surface overhead: 60 of a combat transaction's ~101 carried surfaces are 4-vertex
quads, so the fixed cost per surface (layout, refs, eight small runs) outweighs the arithmetic.
Reaching +10 % likely needs a stream-space un-predict (whole streams at once, the history read
through per-stream offsets) rather than more per-surface tuning; that is a change of its own.

Native `Core::accept` (`rs-core-capi`'s ignored `accept_bench`, minimum of 5 repeats per
transaction, `quiet.sh exclusive`):

| before | 129.2 / 135.7 / 89.2 | 155.8 / 163.8 / 105.9 | +26.6 µs (+20.6 %) | ~10 |
| W13p | 132.3 / 147.8 / 93.3 | 152.4 / 162.1 / 105.0 | +20.1 µs (+15.2 %) | ~6.7 |

## Deviations

- **wasm accept +13.4 %, not ≤ +10 %** (above): the bar is missed by 6.7 µs a transaction.
- **The web export's dlink core has no SIMD**: it gets the history and kernel changes on plain-word
  lanes. Turning `+simd128` on there needs a check that Godot 4.5.1's web template loads such a
  side module.
- **pm-a11-1 and late-1** cannot be transcoded to /13 (they are /11 and /8); their round trip is
  replaced by the g8w11 and g8pt /12 recordings.
- Instruction counts are the host's primary measure; the real-time check is reported with its
  noise, not as the bar.

## Notes

- A crate's `.cargo/config.toml` is read only when cargo runs from that directory (or below):
  `cargo --manifest-path` from elsewhere ignores it, and a `RUSTFLAGS` environment variable
  overrides it. Build rs-gsw-wasm through the two scripts to get SIMD.
- In wasm, 128-bit integer multiplies are library calls; keep them out of hot loops.
- `rs-core-check goldens` needs `--dir <protocol>` unless run from the protocol directory.
- The live hub's typed meta rides on `SharedTx`, so a connection that re-stamps another's /12
  transaction also skips the JSON.
