# W11c: GSW applies render-stream/11 (2026-10-27)

W11c makes the GSW browser receiver (rs-core plus `rs-gsw-wasm`) apply /11
([protocol/render-stream-11.md](../../protocol/render-stream-11.md), "As built (W11c)"):

- dynamic mesh bodies by mesh id, replaced in place, with no payload-store entry per pose;
- the retention rule: the store holds H = names(S_d) ∪ C ∪ names(S_n) and drops a hash the moment
  it leaves (`Validator::released()`);
- `inline-fetch-zero` at both fetchers (`Validator::check_fetch`);
- the live offer `render-stream.11` under `RS_RECEIVER_PROTOCOL=11`, at windows 1 and 2;
- W11t's live coding: GSW offers `live_coding: zstd-base,zstd` and decodes every message in place
  before parsing it (W11t landed while W11c ran; this branch is rebased onto it).

It closes the long-session blocker: GSW's wasm heap no longer grows with the poses it is sent. On
`capture-scale` the /11 heap is flat for 20 minutes (0.0 MB/min, 219 store entries) where /10 grows
174 MB/min (316,908 entries after 3 minutes). In STS2 combat, one live GSW viewer at /11 held a
604.1 MB heap, flat to the byte, for 20 minutes (0.0 MB/min against 5–7 MB/s before), with 276
store entries, applying 59.3 transactions a second; with W11t's coding on, 617.5 MB flat, 59.5
applies a second, at 5.9 Mbps.

/8 to /10 receivers and goldens are unchanged: every /11 path is gated on the version (the
validator's `released()` and `dynamic_bodies()` are empty below /11, and the new evidence keys are
written at /11 only). Two changes reach every version without changing what is applied: the fast
meta path now also reads /8-/10 mesh entries (equal to the general path on every golden), and a
summary log keeps no per-transaction evidence in wasm.

## Decisions

The rules are listed in the protocol doc's "As built (W11c)". In short:

1. **Bodies are decoded at accept, kept by mesh id.** `PayloadStore::accept_transaction(&v,
   record)` right after every accepted transaction (`apply::dynamic::DynamicMeshes`): a live
   message buffer is reused by the next message, and a window-2 fold accepts two transactions
   before one apply. One body per dynamic surface; a freed or emptied mesh drops its bodies. Not
   store entries, not counted by the G7k budget.
2. **Residency rows** for a dynamic mesh: `create`, `rebuild` when a surface's shape or index bytes
   change, else `update` per moved surface with the region buffers (W11d's rule). GSW has no
   per-mesh GL buffers (G7t lowers meshes into the list's shared vertex buffer), so the design's
   `bufferSubData` is the item's in-place re-lower.
3. **Retention** (`apply::retention::Retention`): `note` the released hashes after each accepted
   transaction, `sweep` after each accept and each apply; a hash the display still draws from
   waits for the apply that moves the display.
4. **The fast meta path** now takes /8+ mesh entries, /11's `u8` and null hashes, and integers up
   to 2^53 (16 digits): the /11 `content_version` digests sent every STS2 item to the general
   path.
5. **A summary log keeps no per-transaction evidence in wasm** (G7kh's JS rule extended): at about
   100 mesh rows a combat transaction, the evidence alone would have grown the heap tens of MB a
   minute.
6. **Sabotages** are GSW options (`stale-dynamic-rx`, `evict-carried`, `ignore-released`) and one
   validator switch (`Validator::set_no_prune`, `no-prune`).

## For W11d and W11e

rs-core is shared; a receiver on it calls, per record:

1. `Validator::accept(record, offset)`.
2. On `Accepted::Transaction`, before the record's buffer is reused:
   `PayloadStore::accept_transaction(&validator, record)` (or `DynamicMeshes::ingest(state,
   validator.dynamic_bodies(), record)` with your own store), then `Retention::note(&validator)`
   and `Retention::sweep(&validator, &mut store, || displayed_hashes)`. The capi's displayed set is
   what `RsResourceCache` and the planner hold.
3. After each apply, `Retention::sweep` again.
4. Before each GET, `Validator::check_fetch(&hash)`; a refusal is a receiver failure
   (`inline-fetch-zero`).
5. For evidence, `apply::dynamic::body_sha256` equals the resolved surface's `body_sha256` exactly
   when the held body is right.

The capi planner still counts dynamic meshes undrawn (`meshes_dynamic_undrawn`); W11d replaces
that with region uploads from `DynamicMeshes`. W11t's decode goes first of all, on the raw
message (GSW: `LiveCoding::decode_rx` before `live_session`/`live_accept`); a coding resync
leaves the applier behind the state, so the full transaction that ends it needs a fresh applier,
as an injected resync does.

## Memory-worthy

- The fast meta path read integers of at most 15 digits, so /11's 53-bit `content_version` digests
  sent every STS2 transaction to the general path; 16 digits ≤ 2^53 are what an f64 holds exactly.
- GSW's wasm evidence (`TxEvidence`, mesh rows) grew per transaction even under
  `RS_RECEIVER_LOG=summary`; the summary log now keeps none.
- capture-scale's dynamic meshes move under a pixel a frame: a stale-pose sabotage needs
  `gate6-scene`.
- `c3_recording` in the C3 harness fails under `set -e` when fewer than all four sinks exist; pass
  `C3_REC`.
- `analyze.mts` needs `C3_GSW` (its default worktree is gone) and now tolerates `unsupported: null`.
